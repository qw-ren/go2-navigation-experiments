## 后续 FAST-LIO2 / FAST-LIVO2（本轮不实施）

用户确认纯仿真研究：保留现有 `Hesai_XT32_SD10` RTX 三维雷达，给底盘增加 Isaac 原生 IMU；不依赖雷达或 JetBot 资产自动提供 IMU。迁移 JetBot 时检查实际 USD，必要时挂载同类 IMU。

当前传感器创建代码无独立 IMU/ROS Imu 输出；点云 Bridge 仅 XYZ。先验证正确的加速度（含重力约定）、角速度、坐标系/外参，以及统一的仿真测量时间，再适配 FAST-LIO2 点格式和逐点时间。

禁止用无效 RTX 辅助时间字段或任意填充的逐点时间冒充去畸变输入。此前辅助通道失败记录继续保留；若原生输出无法可靠满足要求，需明确设计并验证扫描采样/时间模型后再接入。`common.time_sync_en` 按 AGENTS 保持 false，除非取得新的同步证据。

原 Go2 环境 `sim.dt=0.005`，物理步进名义为 200 Hz；传感器是否实际每物理步采样需另行验证，不能把 50 Hz 控制循环数据重复发布当成 200 Hz IMU。

现有相机是 Isaac 通用 Camera：640×480、焦距参数1.5，RGB/Depth/CameraInfo。保留用于后续 FAST-LIVO2；接入前核对内参、光学坐标、雷达/相机外参、视场重叠、真实采样频率与测量时间同步。相机现有并不等于 LIVO2 已满足全部输入要求。

估计里程计、仿真真实位姿与地图定位职责分开：真实位姿用于评估；现有 SLAM 建图仍用了真实 odom 输入，需要明确披露。接入 LIO 时保证 `odom→base_link` 唯一发布者，先平行评测再切换导航输入。
